## 1. 要件と範囲

- [ ] 対象資格・Version、読者、教材言語、作業範囲、生成元、既存変更、公開経路を確認した。
- [ ] 明示された指定を既定値より優先し、既存言語・有効なID・承認済みの範囲を維持した。
- [ ] [講座設定](course-settings.md) の共通品質要件と個人用既定値を区別し、今回の成果物へ適用する設定・検査を決めた。
- [ ] 会話の言語と教材言語を分け、Navigation・本文・解説・生成Templateの言語が一致している。
- [ ] 判断記録やSkill更新は [記録の適用範囲](adr-and-skill-evolution.md) に従い、依頼外の変更を増やしていない。

## 2. 公式情報と試験対応

詳細: [Source分析の観点と集計](source-analysis-method.md)、[試験対応](exam-question-fidelity.md#1-問題作成前のevidence-gate)、[文体とSourceの優先順位](source-calibrated-question-writing.md)。

- [ ] 現行公式範囲・Weight・許可形式を確認し、Sourceの観察頻度と公式比率を混同していない。
- [ ] 今回の問題・解説Sourceの完全例、断片、重複、未観察部分を区別し、採用する特徴を記録した。
- [ ] 種類・割合の分母と実読範囲、比較意図と成立の違いを示し、観測値→通常問題・各Mockの採用件数→本文で確認した実件数を追跡できる。
- [ ] 主要形式・長短・判断が異なる完成例をSourceと読み比べ、量産前に文体を校正した。
- [ ] Source未観察の公式Objectiveも、一次情報と観察した出題化Patternから設計している。
- [ ] 技術的正答性に直接対応する公式Source、確認日、Versionを追跡できる。
- [ ] Login必須・未発見・旧版を記録し、確認できなかった資料を閲覧済みとしていない。

## 3. 講義の理解しやすさ

詳細: [講義の読みやすさ](lecture-readability-standard.md)。

- [ ] 目的から仕組み・処理・具体例・判断へ進め、専門語を未説明の専門語だけで定義していない。
- [ ] 名前・推奨ControlだけのSourceを共通文で膨らませず、概念固有の因果関係を保持している。
- [ ] 講義間の共通文を抽出し、必要な用語・安全注意と、不要な導入・結論・末尾一覧の複製を分けた。
- [ ] 見出し数・語数・用語Linkだけを説明の深さとして合格させていない。
- [ ] 講義・LabのInline questionにも候補固有の理由があり、Open responseは期待判断と採点根拠を持つ。

### 3.1 包括性と問題前提閉包

詳細: [学習契約と再制作順](lecture-completeness-and-prerequisite-closure.md)、[Service表記のLink](service-mention-linking.md)。

- [ ] 資格Levelだけを理由に下位資格・製品経験を暗黙の前提にしていない。
- [ ] 正規問題本文から必要知識を抽出し、全IDと `learning_requirements` がManifestと一致している。
- [ ] 問題本文・全候補・全解説と必要知識一覧を照合し、未登録Serviceや暗黙の前提の抽出漏れを意味Reviewした。
- [ ] 必要なFoundation・Service・Artifact読解・Integrationを問題前に学べる。
- [ ] サービス学習の導線を採用した場合、学習契約の配置・固有講義・説明観点と、リンク基準の表示検査を満たした。
- [ ] 全面再制作ではDraft問題→必要知識→新講義→Link割当て→正式Reviewの順に進め、旧本文をSeedにしていない。
- [ ] Draft Snapshotと最終Hashを区別し、正式Reviewの後でLinkを付けて台帳を無効にする手順を避けている。

## 4. 用語集と導線

詳細: [用語導入](lecture-readability-standard.md#3-専門用語の扱い)、[複数講座のNavigation](multi-course-site-navigation.md)。

- [ ] 用語の平易な意味・具体例・必要な比較があり、本文と用語集を往復できる。
- [ ] 講座入口、前提、Services、講義、問題、模擬試験の行き先が分かる。
- [ ] Link・Anchor・Breadcrumbが対象講座内の正しい場所へ到達する。

## 5. ハンズオン

詳細: [無料環境と安全](free-environment-safety.md)、[ハンズオンの代替](exam-question-fidelity.md#5-ハンズオンを省略したい学習者への代替)。

- [ ] 開始条件、成功時の観測、失敗時の確認、停止・削除まで再現できる。
- [ ] 無料枠・Quota・期限・支払条件を現行情報で確認し、BudgetやAlertを課金上限と説明していない。
- [ ] 任意Labの代替でも同じ判断を測り、実環境固有の操作まで代替したとは主張していない。

## 6. 通常問題と模擬試験

詳細: [件数と制作](question-bank-quality-standard.md)、[問題・選択肢の執筆](source-calibrated-question-writing.md)、[解説](explanation-writing-standard.md)、[Artifactの妥当性](exam-question-fidelity.md)。

- [ ] 通常問題と各Mockを分け、指定件数・公式Coverage・形式配分が一致している。
- [ ] 全面再制作、追加、限定修正を区別し、既定件数のためだけに有効な既存問題を削除していない。
- [ ] 必須要件と評価軸を分け、実現可能だが運用負荷・費用・性能で劣る候補も正しく扱っている。
- [ ] Multiple Responseの独立解決策と組合せを区別し、Orderingの選択・不採用・使用回数、Matchingの再利用可否を守っている。
- [ ] 正誤すべての候補に固有の採否理由があり、固定４文・一律の長さ・共通結論で埋めていない。
- [ ] Stem／Option／両方／なしのArtifact分類と、各Surfaceの明示件数・指定時だけの比率を検査した。
- [ ] Option Artifactの全候補が実体を持ち、共通検証・Binding・解説・表示が対応している。
- [ ] 同じ出力の候補でも比較根拠を確認し、異なる原因で同じ結果になる誤答を拒否していない。
- [ ] 実質重複、答え漏洩、正答だけの長文、誤答に偏った語彙・破壊操作を横断Reviewした。
- [ ] Artifactの整形、依存関係、製品Schema、Return型を検査し、構文だけ通る不完全な実装を正答にしていない。

## 7. 問題品質レビュー

詳細: [初回の全問Review](question-bank-quality-standard.md#6-全問をレビューする)、[変更時の再レビュー](review-update-policy.md)、[台帳と検査の保証範囲](question-bank-validation-procedure.md#3-二段階reviewをhash付きで記録する)。

- [ ] 全問の構造検査、意味Review、横断Review、必要な独立Reviewを完了した。
- [ ] 台帳のID・状態・修正理由・Hashが完成問題と一致している。
- [ ] 確認済み版の変更では、内容・表示・依存先への影響を調べ、過去の有効な確認と今回の実確認から現行版の判定へ戻れる。
- [ ] 独立Reviewは実担当者の確認記録・範囲・Hashを照合し、異なる名前の台帳だけで完了扱いにしていない。
- [ ] Blocker・Majorが0件で、残したMinorはID・理由・影響を記録した。
- [ ] 機械検査の成功と、Sourceへの文体適合・説明の理解しやすさを区別している。

## 8. ソースと回帰防止

詳細: [検証手順](question-bank-validation-procedure.md)、[生成元の責務](question-bank-quality-standard.md#5-生成元を設計する)。

- [ ] 正規Sourceを直し、通常の再生成で同じ修正結果が得られる。
- [ ] 候補変更時にStem・正答・全解説・Evidenceを一緒に更新し、古い本文を上乗せしていない。
- [ ] 変更した検査に、実際の不具合を再現する失敗例と、許容すべき正常例がある。
- [ ] テストの正常例をID・名称だけの複製で作らず、検査関数の中間結果も必要な範囲で確認した。
- [ ] 指摘された反復文は発生元を直し、必要な共通用語まで禁止語検査で消していない。
- [ ] Label変更は実際の選択肢参照だけを更新し、英文の不定冠詞・製品構文を壊していない。
- [ ] 翻訳と修復処理を併用する場合、入力Hash・処理順・未知Drift時の失敗を確認した。
- [ ] 改行・順序・追加・削除を含む生成再現性と、ローカル／CIの必須検査の一致を確認した。

## 9. Web表示

- [ ] 厳格Buildが成功し、正規Sourceと生成Markdown／HTMLの本文・正答・Artifactが一致する。
- [ ] Code・表・長い選択肢が読め、Mermaidが通常のCode blockへ露出していない。
- [ ] Navigation、深いURL、アセット、検索、解答表示など変更に関係する操作を確認した。
- [ ] ブラウザ未使用時は、静的HTMLで確認した範囲と操作・描画の未検証部分を分けた。

## 10. 外部サービスと公開

- [ ] 新しい外部サービス・費用・権限・公開範囲は、実際の依頼と承認済み範囲に収まっている。
- [ ] サイト公開をSource Repository公開の許可とみなしていない。
- [ ] 公開が依頼範囲ならCI完了と公開先への反映を確認し、代表ページだけで全対象の反映を断定していない。
- [ ] 特定の反復文除去が目的の場合は、対象ページと検索Indexへの残存も確認した。

## 11. 最終報告

- [ ] 変更範囲、書き方の改善、検証結果、残る制約を簡潔に示した。
- [ ] 詳細Evidenceは追跡でき、未確認をPASS・公開確認を内容品質の証明としていない。
- [ ] Skillだけの変更、教材変更、公開反映を実施した範囲どおりに報告した。
