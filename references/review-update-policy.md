# 変更の影響に応じた再レビュー

確認済み教材の修正時に、再確認する範囲と記録を決めるために使う。初回の全問レビューや正式確認前のDraftを省略する規則ではない。台帳の形式・Hashの算出・実担当者の照合は [検証手順](question-bank-validation-procedure.md#3-二段階reviewをhash付きで記録する) を正規定義とする。

## 初回と再確認を分ける

新作・全面再制作の初回は、対象全問の意味レビューと独立レビューを完成した問題・表示で行う。問題→必要知識→講義→リンク割当ての順に制作し、途中の校正を正式完了として記録しない。

確認済み版を修正する場合は、前後の原稿と表示の差分から下表の確認範囲を決める。複数種類に該当すれば範囲を合わせ、不明なら内容変更として扱う。ファイル名、変更行数、作者の「軽微」という申告だけで分類しない。

| 変更 | 必要な確認 |
|---|---|
| 正答、条件、数値・演算子、候補、解説の理由、コード・設定、技術的根拠 | 変更問と影響問の正答性・一意性・全候補の理由を再レビュー。必要知識と影響講義、形式・配分・重複への影響も確認 |
| 講義本文、前提知識、サービス仕様 | 該当講義と依存する問題の理解・正答性への影響を確認。問題ファイルが同じHashでも、参照先の意味が変われば対象に含める |
| 内部リンクの移転・Anchor変更だけ | 表示文、正答、候補、解説、参照先の意味と前提知識が変わらないことを前後比較。全変更リンク、到達先、表示、生成再現性を検査。前提が変われば上段へ戻る |
| 誤字、段落、文言の整形 | 数値・否定・条件・候補間の差・コード等の意味を変えていないか読む。変化があれば内容変更として確認。表示上の欠落や答えの漏れも確認 |
| 選択肢の並べ替え、Renderer、共通テンプレート、分類・配分処理 | 正答参照、解説、対象全出力、集計を検査。共通処理の影響範囲で確認し、一問の成功だけで完了にしない |
| 原稿・表示・依存する根拠に変更なし | 固定した既存の確認記録を利用できる。検査対象との一致と記録の有効性を確認 |

リンク修正でも必要な初回レビューが未完了なら、差分確認だけで完了にしない。独立レビューが必要な対象では、各役割の実担当者が自分の確認範囲と完了を記録する。差分の意味不変を確認できれば、過去に確認済みの技術事項を最初から調査し直す必要はない。

## 現行版へ記録をつなぐ

既存の実記録へ、対象ID、旧・新Hash、変更内容、影響範囲、参照した過去の確認記録、今回実施した検査と結果、担当者・日時を残す。別の固定Schemaや必須台帳を追加する必要はない。

`question_hash` は講義リンクを含む完成問題全体に対して再計算する。Hashの対象を削って変更を隠さず、古いHashのPASSを新しいHashへ自動転記しない。現行版の台帳行は、過去の有効な確認と今回の実際の差分確認の両方へ戻れるようにする。変更問の判定は確認後に担当者が確定する。

同梱CLIが証明するのは台帳と現行Hashの整合までであり、差分の意味不変や過去記録の再利用妥当性は別途確認する。記録が不足する場合は必要なレビューを実施し、未確認を完了にしない。最終版で全対象の確認範囲が閉じ、既存の必須検査が通ることを引渡し条件とする。
